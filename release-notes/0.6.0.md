A minor release: the kernel carries the uncertainty of a group curve. The parametric bootstrap and the delta method run inside `analyze_batch`, so a host gets the uncertainty in the call it already makes and a browser gets it with no second round trip, and `bootstrap_normals` hands the same draws to a host whose own engine analyses a batch this build refuses.

## The draws

`bootstrap_normals(seed, start, count)` is the new python entry point: the standard normal draws of a range of flat indices, as a `float64` array. They are a counter-based generator (Philox4x64-10 of Random123) and not a stream: the draw of an index is a function of the seed and that index alone, so a range asked for in pieces is the range, a shard reaches the draws of its own rows without drawing the rows before it, and a host which analyses a batch itself gets exactly the numbers the kernel would have used. At most 16 Mi draws in one call; a longer range is asked for in pieces.

The stream is checked against `numpy.random.Philox` word for word, which is the same algorithm, and the normal transform is the inverse cumulative distribution function, deliberately: a ziggurat or a rejection transform consumes a variable number of uniforms per normal, which would make the position in the stream depend on the values drawn before it and the index would stop being a position.

Reproducing `numpy.random.Generator.standard_normal` is explicitly not a goal. numpy promises its stream only on the same build, in the same environment, on the same machine, and reserves the right to change a distribution method; this one promises the same numbers on every platform, in the browser and across numpy releases, which is the stronger guarantee and the reason a host asks the kernel for its draws rather than drawing its own. A host which moves its bootstrap here will see its confidence bounds move, by the sampling difference between two sets of draws and by nothing else.

## The uncertainty inside the analysis

A result of a group batch whose options resolve to a method now carries the uncertainty of every continuous parameter: `x_sd`, `x_se`, `x_ci_low`, `x_ci_high`, `x_pi_low` and `x_pi_high` under `sd` draws, and `x_geomean` and `x_geocv` for a log-normal parameter.

- the parametric bootstrap resamples every point of every row around its own value with its own spread, normal or log-normal on the log scale (so a spread whose relative square overflows still draws), analyses every replicate curve through the same code the original rows go through and reduces the replicates. The rows are cut into blocks, so only the draws, the replicate rows and the parameters of one block exist at once; the block size changes no number, since every draw is asked for by its index in the whole batch.
- the delta method perturbs every point once by `max(delta_step * se, nextafter(0, 1), sqrt(eps) * |c|)`, uses the representable increment as the denominator and accumulates `var(x) = sum (dx/dC_i)^2 se_i^2` with `hypot`, never by squaring first. A perturbation which selects another terminal window is a jump between two regressions and not a derivative: such a point is skipped for every parameter which reads the window and the row carries `NcaFlag::DELTA_WINDOW_CHANGE`, which says that the uncertainty of its terminal parameters is incomplete.

## What a host has to get right

A bootstrap whose seed the options leave open is **refused by name** (`is_supported`), because the kernel reads no entropy: it has none in a wasm instance, and a kernel which reached for the operating system would not build for one. A host draws the seed itself, before it asks, and then the analysis runs; a host which forgets takes its own path instead of failing. Log-normal draws of an effect curve are a `ValueError` with python's own sentence, as in the library.

The uncertainty columns join `AnalysisResult.parameters` after the parameters themselves and carry the unit of the parameter they belong to, `x_geocv` being dimensionless. Their order is the library's: a log-normal parameter carries its geometric statistics in front of the four variables every parameter has.

## Compatibility

No change to `batch/1`, `analysis/1` or the options. `UncertaintyMethod`, `n_boot`, `seed`, `ci_level`, `bootstrap_spread` and `bootstrap_distribution` were already on the wire and did nothing; a result of a group batch under a resolved method now carries more columns than it did in 0.5.1, which is the one behaviour change of this release. `pkpdutils` 1.7.0 moves its floor here.
