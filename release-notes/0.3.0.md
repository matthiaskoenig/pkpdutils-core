A minor release: the kernel now analyses multiple dose batches, which it refused until 0.2.2, so a host can route them here instead of to its python core.

## The multiple dose analysis

A row whose protocol holds more than one dose, or any row when `NcaOptions.tau` is set, is analysed over its dosing intervals, as `compute_steady_state` of the python package does:

- the point parameters (`cmax`, `tmax`, `clast`, the terminal phase, `cl_f`, `vz_f`, `mrt`, ...) are computed from the last dose on, with times relative to it;
- the steady state variables of the last complete interval (`auc_tau`, `cmax_ss`, `cmin_ss`, `ctrough`, `cavg`, `fluctuation`, `swing`, `ptr`, `cl_ss_f`, `tau`) and the accumulation ratios against the first interval;
- the per-interval variables `interval_*` over the dimension `interval`, which `NcaOptions.intervals` switches off;
- `tau` is taken from `NcaOptions.tau`, and from the last gap of the protocol where that is unset, so an irregular protocol uses its final gap and not an average;
- a last interval whose last sample falls short of its end by at most `NcaOptions.tau_tolerance` (0.1 of `tau`) is completed with the terminal regression and reports `auc_tau_extrap_fraction`.

A batch may mix single and multiple dose rows. Each row takes its own path and reports `NaN` in the variables of the other one; `n_doses` is the size of the protocol for every row, a single dose row included, while `tau` is `NaN` for a single dose row.

## Two flags the kernel now sets

- `INCOMPLETE_INTERVAL`: the last dosing interval is not covered by the data.
- `EXTRAPOLATED_TROUGH`: the trough of a bolus interval was regressed, because the sample at the dose time carries the post-dose value.

Both are raised whether or not the interval variables are emitted.

## The centred trough regression

The normal equations of the log-linear regression which replaces the trough of a bolus interval subtract two nearly equal sums, so on absolute times they lose digits once the times are large relative to their spread; the python package measured an error of 2.4e-07 at t of about 1000 with a spread of 0.1. The fit is now made about the centroid of the selected samples, with times and log values both centred. It is the same line algebraically, and the kernel and `pkpdutils` (#130) apply the same arithmetic.

## Refusals lifted

`analyze_batch` and the python binding no longer refuse a multiple dose batch or an explicit `tau`. What is still refused is unchanged: an effect curve, the acceptance criteria, the named partial areas, the propagation of an uncertainty and the unit conversion of a result. `is_supported` reports them all from one place.

## Tests

`crates/oracles/tests/multiple_dose.rs` pins the new path against the python core of `pkpdutils` on nine cases written by `scripts/multiple_dose_oracle.py`: regular oral, bolus with a regressed trough, an irregular protocol, a completed and an incomplete last interval, a mixed batch, three infusions, a single dose with a `tau`, and a run without the interval variables. The steady state and interval variables are compared bit for bit, every other column at a relative 1e-12.

## Documentation

The README says how to run the tests: `cargo test -p pkpdutils-core` for the kernel alone, and `PYO3_PYTHON=python3.13 cargo test --workspace` for the binding, from an activated virtual environment with numpy, where the default `python3` predates the `abi3-py313` floor.

## Compatibility

No change to `batch/1`, `analysis/1` or the options. `pkpdutils` can move its floor to this release to route multiple dose batches to the kernel.
