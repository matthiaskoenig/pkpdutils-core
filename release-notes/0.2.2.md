A patch release: one numerical fix in the terminal regression, and the regenerated pint gate.

## The standard error of an exact terminal fit (#4)

`window_statistics` computed the residual sum of squares of a window as `syy_c - slope * sxy_c`, two quantities which are equal for a perfect fit, so a noise free curve left only the rounding of the sums behind and its sign was arbitrary. Clamping at zero then reported either `0.0`, where the rounding went negative, or the square root of that noise, around `1e-9`, where it went positive.

The kernel and the python core of `pkpdutils` therefore disagreed on half of a noise free batch, which the engine gate caught on linux while the same commit passed elsewhere. The residual is now taken as zero below the rounding of its own operands, with the identical floor on both sides, so an exact fit reports exactly `0.0` on every platform.

The floor is written against the uncentred `syy` and not against `syy_c`, because every window of a row shares one origin, the row's first sample, so a short window late in the curve has `syy` and `sy * sy / n` both of the order of the whole drop while their difference is small. The multiple is 16 from measurement over 120 000 windows: the ratio `|ss_res| / (n * eps * syy)` reaches 1.20 for a noise free curve and stays above 1.9e+05 for a curve of 1 % noise from four samples up.

This affects `lambda_z_stderr` and the confidence interval derived from it. Any curve carrying real noise is untouched.

## The pint gate (#3)

`crates/units/tests/data/pint_gate.json` is regenerated against the merged python host, 6059 records and 42 spellings, which adds `nmol`, `nmol/l` and `mg*min/l` among others. Test data only.

## Compatibility

No API change. `pkpdutils` requires this release from its next version on, since the two engines must apply the same floor to agree.
